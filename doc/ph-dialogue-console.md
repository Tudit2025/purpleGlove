# 对话与测试控制台

主场景：`Assets/Art/DeskSceneV1/Scenes/PH_DeskRoom.unity`。进入 Play Mode 后按 **F1** 或 **反引号** 打开章节测试面板，点击目标幕，从该幕开场开始。**Esc** 关闭面板，继续当前演出。

## 跳转到各幕开始

| 入口 | 起点与准备的状态 |
|---|---|
| 第零幕 · 门槛 | 门外独白，所有卷宗未收件；随后自然进入第一幕 |
| 第一幕 · 留下原件 | 幕名转场、敲门、执事介绍，再接收棕白包裹 |
| 第二幕 · 第七号封档 | 第一幕原件与明文已归档；贝阿特丽切介绍后接收第二幕封包 |
| 第三幕 · 读得通的谎言 | 前两幕含补充文件与两段第二幕明文均已归档；介绍后接收军情，核验签名仍需玩家完成 |
| 第四幕 · 名字留在纸上 | 前三幕完成，夏尔凭条及已签核验表保留；介绍后接收双封包，两段密文尚未解开 |
| 第五幕 · 落笔与交卷 | 前四幕完成，全部明文与核验签名保留，自述可阅读；介绍、收件后开始选择担保、原件去向及是否焚毁 |
| 第六幕 · 尾声 | 按所选结局准备已交卷状态；幕名转场后从六点回报开始完整演出 |

第六幕提供四个预设：“开门”为不签保证、原件留存、保留自述；“缺页”仅改为烧毁自述；“真相易手”为不签保证、移交威尼斯、保留自述；“背书”为签保证、原件留存、保留自述。需要测试其他去向组合时，从第五幕开始自行选择。

每次跳转重新载入当前场景，清空本次游玩的草稿、选择、焚毁、物品姿态及演出状态，再准备目标幕之前的原件、补充文件、明文和签名。目标幕的文件仍须按正常剧情收件，谜题和选择由玩家继续完成。重复进入同一幕、在对话或收件中跳转、从尾声黑屏返回均使用相同入口；打开面板而不跳转不会重开剧情。尚未接入跨运行存档。

旧的事件试播、独立收件、命令输入及中止／继续按钮已移除。场景组件的 `Stop()` / `Resume()` 等接口仍供流程与开发检查使用。跳转入口为 `DialogueTestConsole.JumpToAct(int, EndingPreset)`，幕号范围 0–6；重复加载请求会被拒绝。当前场景需加入 Build Settings，主场景已配置。

验证脚本及结果位于 [chapter-jump-validation](../output/chapter-jump-validation/)：独立 Unity 项目副本中，14 次实际异步场景重载、607 项检查通过，覆盖第零幕至第六幕、四种尾声、此前证据与签名、开场收件后继续解谜、收件中跳转、焚毁后重开及最终黑屏返回第一幕。

门边交谈与收件采用默认 0.85 秒的缓入缓出镜头过渡，从当前机位连续调整位置、朝向与视野；主摄像机 `DeskScenePreview.doorwayTransitionSeconds` 可调时长。交谈时先等镜头到位，再完整播放观察窗向上翻开的动画，开窗结束才显示第一句。读完最后一句后，先合上观察窗，再结束事件并让镜头返回；关窗期间保留门边机位与输入锁。观察窗开合沿用 `DoorMechanism.travelSeconds`（默认 0.55 秒）与机械音效。`Stop()` 会立即中止对话、释放输入，窗板从当前角度动画恢复，镜头平滑返回原机位。

## 第零幕与幕间转场

按 **F1** 点击“第零幕 · 门槛”。镜头切到门外短廊，以工作间门为主体，播放 [修订剧本](ph-revised.md) 中第零幕的 11 句台词：卢卡独白、画外执事交代、卢卡确认进入。使用原有角色文字颜色、逐字速度和发言音效，执事不显示人物图像，也不打开探视窗。空格／回车／左键逐句推进，最后一句“让我进去”之后再次推进即开门。

门扇绕原有铰链向室内打开，停留片刻后淡出；全黑时关闭门并切回桌面，淡显“第一幕”，停留，再隐藏幕名、淡入第一幕桌面。默认淡出 0.8 秒、纯黑停顿 0.3 秒、幕名淡入／淡出各 0.45 秒、幕名停留 1.6 秒、画面淡入 1 秒。雨声与场景环境音继续播放，开关门使用现有木门音效。

章节测试会先准备此前的完成状态，再播放目标幕的转场和开场。目标幕文件在玩家接收包裹、包裹落桌后解锁。控制台打开或窗口失焦时暂停演出时钟；演出期间锁定场景点击、WASD、滚轮与解密输入，控制台始终可用于重新跳转。

`PrologueSequence.BeginPrologue()` 可绑定剧情 UnityEvent；`ShowAct(int)` 为幕间转场入口，淡入完成后触发 `actEntered(int)`。`ActTransitionOverlay.Begin(int, Action, Action)` 可复用到后续幕次，第一项回调只在全黑时执行，第二项回调在淡入完成后执行。安装菜单为 `Purple Glove > Dialogue > Install Prologue and Act Transitions`，完整对话安装也会接入；重复安装保留已编辑的台词资产与演出参数。预览脚本与结果位于 `output/prologue-validation/`。

## 物品首次互动回忆

旧版与七瓣花版《祷文集》、师父的旧笔记、解密工具箱各有一句卢卡的回忆独白。第一次点击时沿用当前镜头，显示卢卡的对话面板；读完后自动继续查看物品或打开工具箱。悬停不触发，桌面与解密俯视下的工具箱入口共用一次记录。每件物品在本次游玩中只介绍一次，切幕后保留记录；重新进入 Play Mode 后重置，尚未接入跨运行存档。组件中途取消后，下一次点击会重播。

台词保存在 `Assets/Data/Dialogue/Events/memory_prayer_old.asset`、`memory_prayer_flower.asset`、`memory_notebook.asset`、`memory_toolbox.asset`。其他采用 `SceneObjectInteractor` 点击入口的物件可添加 `FirstInteractionMemory`，指定主摄像机的 `DialogueController` 与回忆 `DialogueEvent`；自定义交互入口可调用 `TryBegin(继续交互的回调)`。菜单 `Purple Glove > Dialogue > Install First Interaction Memories` 安装这四项配置，完整场景构建与对话安装也会接入；重复安装保留已编辑的台词与自定义事件引用。验证脚本、242 项 Play Mode 检查结果及截图见 `output/object-memory-validation/`。

## 播放与操作

- **空格、回车、鼠标左键**：打字中显示完整的一句；打字完成后进入下一句。最后一句之后结束事件。
- **玩家选择**：提示与多个回应同时显示全文，不逐字出现，也不播放发言或点击音效。鼠标悬停高亮，点击一个回应才继续；空格、回车和空白处点击都不会代选。控制台打开时暂停选择。
- **F1 / 反引号**：打开或关闭控制台；控制台打开时暂停文字和发言音效。Esc 只关闭控制台。
- 来访对话开始时放回正在查看的物件，打开探视窗并锁定看门机位；物品回忆保持原机位。WASD、鼠标视角偏移、物件点击和翻书都不能打断对话。
- 结束、测试中止或禁用对话组件后，恢复进入对话前的机位与探视窗开合状态；最后一次点击不会落到物件上。
- 平时不自动播放测试对话。控制台默认在编辑器和 Development Build 中可用；正式构建可在 `DialogueTestConsole.enableInReleaseBuild` 中显式开启。

普通台词仍使用一个面板：卢卡位于下三分之一，其他角色位于中三分之一。面板仅显示当前一句台词，不显示人物名称或交互提示；正文使用面板内的完整区域并保留边距，空格、回车和鼠标左键仍可补全或推进台词。玩家选择复用此面板，在屏幕下方显示提示与纵向排列的回应，随选项数量向上扩展。场景和眼睛保持像素采样，文字通过独立 UI 摄像机以屏幕分辨率绘制，保留中文笔画。整句先排版，再逐字显现，隐藏的后缀仍保留位置，避免换行跳动。中文、代理对和组合字符按完整文本元素推进，标点处略作停顿。

第五幕拿起手摇铃后，先选择“摇铃，按当前安排交卷”或“暂不摇铃”；前者才开始摇响，后者放回铃并继续处理文件。点击师父自述的焚毁区域后，先选择“烧毁”或“保留”；只有选择烧毁才将纸移向烛火，保留则继续阅读。中止选择不会摇响、焚毁或交卷；确认摇铃后的铃声及原有动作音效照常播放。

在 `DialogueEvent.Line.choices` 配置两个或更多回应，每项包含同一节点内唯一的 `id`、显示文字 `text` 和从零起算的目标台词 `nextLine`；`nextLine = -1` 表示结束事件。选择节点的提示与回应均立即完整显示、静音。未配置选项的台词保持原有打字与声音行为。`DialogueController.SelectChoice(index)` 执行选择，`SelectedChoiceId` 提供最近结果；`choiceSelected(eventId, choiceId)` 通知具体选择，正常结束仍触发 `eventCompleted`。第五幕的两组选择在运行时创建，无需重新安装场景。

## 明文完成与留存

留存字条只显示英文明文与中文译文，去掉“明文留存”、来源名称、幕次及“卢卡译录”等补充标签。

第一至第四幕，明文通过该幕谜题答案的容错校验后，等待最后一片字母木片归盘，再自动生成可检视的明文留存纸，加入当前桌面所展示幕次的文件。每幕第一次完成时，卢卡通过现有对话面板说“完成了。把这份明文留好。”，保持当前镜头。第二幕的书本／猪圈、第四幕的仿射／栅栏分别留存，完成提示每幕只播放一次；第五幕不生成明文文件。

答案匹配忽略大小写、空格、换行和标点，按剩余字母／数字的编辑距离允许最多 10% 的错漏：替换、遗漏或多输入一个字符各计一次，以标准答案的有效字符数为分母，允许次数向下取整。例如 15 个字符可错漏 1 个，20 个可错漏 2 个，少于 10 个字符仍须全部正确；超出额度或空白草稿不保存。每份明文确认并成功留存后，自动清空书写区及本幕草稿，下一份答案可直接填写；未通过校验、等待落字或文件尚未解锁时保留输入。每个谜题只生成一张文件；文件仍按完整标准答案和词间空格排版，并附剧本中的中文译文，后续修改草稿不会覆盖已经留存的记录。切幕时分别保留各幕尚未确认的草稿，已清空的草稿在回看旧幕或 F1 跳幕补全历史记录后保持空白；归档与取回保留原文件实例和内容，状态限本次游玩。第一幕已接入下述自动推进，其他幕次仍由各自的剧情流程控制。

明文书写字号由 `0.0013` 调至 `0.0021`，约增大 62%；按实际字宽自动换行，纸面显示最近三行，完整草稿保留。木片落字按字体行高和字形位置对齐。主摄像机 `PlaintextArchiveController` 管理判定与留存；`Purple Glove > Acts > Install Plaintext Archives` 可更新现有场景，完整工具区构建亦会接入。完成独白位于 `Assets/Data/Dialogue/Events/plaintext_complete.asset`，验证脚本与画面见 `output/plaintext-archive-validation/`。

专项验证通过 476 项检查，涵盖六段答案、第五幕排除、分幕草稿、归档取回、去重、落字时序与新字号边界；另通过 953 项键盘解码回归。验证采用 Unity Play Mode 中的键盘／指针及帧时序回放。

10% 错漏容错与确认后自动清空通过 [691 项专项检查](../output/plaintext-tolerance-validation/validation.txt)，覆盖六段当前答案的错字／漏字／多字边界、短答案取整、混合错漏、连续答案分界，以及实际 Play Mode 中的收件限制、落字等待、确认时同步清空书写区与草稿、未确认输入保留和归档回看；[验证脚本](../output/plaintext-tolerance-validation/PlaintextToleranceValidation.cs) 在独立工程副本运行。F1 跳幕另通过 [615 项回归检查、14 次异步场景重载](../output/plaintext-tolerance-validation/chapter-jump/validation.txt)，确认历史明文仍完整留存、已完成章节草稿为空且各幕流程可继续。

## 第一幕流程

### 第一幕入场后的交付

序幕进入第一幕，或通过章节测试进入第一幕后，`FirstActFlow` 等待五秒，再完整播放执事敲门音效。声音结束后进入 `act1_arrival` 门边对话，执事说明白色包裹中的公爵核验委托，以及棕色包裹中的会长来信、师父寄存封袋和行会档案转交申请表，并交代申请表先收入桌面立夹。最后一句读完，观察窗完全关闭后，自动接入原有第一幕送件事件。玩家仍需点击接收棕、白包裹，等包裹落桌后才能阅读文件。

计时从转场淡入完成开始；控制台或窗口失焦时暂停。本次运行中回看旧幕不重复交付，通过章节测试重开第一幕则重新播放完整开场。台词位于 `Assets/Data/Dialogue/Events/act1_arrival.asset`；`openingDelay` 默认为五秒。

### 第一幕解读后的自动推进

第一幕正确明文实际留存、最后一片字母木片归盘后，`PlaintextArchiveController.plaintextPreserved(1)` 启动 `FirstActFlow`。五秒后门口响起敲门声；若“完成了。把这份明文留好。”尚未读完，保留当前文字，待读完后再进入 `act1_secretary` 门边交谈，不重复敲门。当前演出采用剧本的“这是两件事”回应。交谈结束后关闭探视窗，镜头在 0.75 秒内回到桌面主机位，再以现有面板播放 `act1_summary` 的三句卢卡自言自语。

总结读完后播放第二幕转场。黑场中收起第一幕资料、备用蜡烛变为三根；淡入完成时正式归档第一幕，再播放既有 `beatrice` 介绍并启动第二幕封口袋收件。第二幕文书仍须点击封袋、落桌后才解锁，第一幕原件及明文保持同一份物体，随时可从书架取回。重复输入、修改草稿、回看旧幕均不重新触发这条流程。

控制台或窗口失焦暂停倒计时与演出。`Stop()` 中止自动流程并恢复当前机位／输入；转场尚未完成时会恢复第一幕材料和四根备用蜡烛，收件中止不解锁第二幕文书。`Resume()` 从被中止的阶段继续，已完成的归档不重复执行。状态限本次运行。`Purple Glove > Acts > Install First Act Progression` 可单独接入，完整场景及明文留存安装也会接入；重复安装保留已编辑台词、事件引用和时长。台词在 `act1_secretary.asset`、`act1_summary.asset`，书记官沿用现有书记员眼部和打字音素材，独立的 `ducal_secretary.asset` 可替换外观与声音。验证记录与截图位于 `output/first-act-flow-validation/`。

## 封口袋收件事件

第一幕收件使用棕、白两个叠放包裹，点击任一可见包裹接收整批；悬停、飞向桌垫、落桌后解锁的流程相同。落桌后展开公爵核验委托、行会会长来信和师父旧密文纸三张文本。会长信为完整明文，收件即可阅读，随第一幕卷宗保存、取回。两封长信并排置于桌垫上方，旧密文纸在下方。委托包含卡拉法代领范围及军情今晚稍后送达的说明，使用思源宋体与 EB Garamond，页眉、页脚带冠徽卷草。旧纸较小，有三个实体裁口，保留 `NHHS WKH RULJLQDO` 与“七瓣花，新版”提示；第一次拿起时卢卡回忆凯撒位移三，纸张持续保持检视，读完可继续阅读。第二、三、五幕使用单包裹；第四幕使用两个并排、各自封缄的独立封包。

同批第四张文书为“行会档案转交申请表”，落桌收件后直接收入立夹，不默认铺开。它记录拟转交的行会档案编号、名称、清单、受领方、事由及申请签名；第五幕开放米兰、威尼斯、法国与继续封存四个纸面选项，选择单方转交时填写申请签名。填写申请不等于已经签收，实际交接统一在摇铃后办理。

菜单 `Purple Glove > Acts > Install First Act Details` 更新第一幕文书与包裹；完整文书构建及收件安装也包含对应配置。师父回忆台词在 `Assets/Data/Dialogue/Events/memory_three_cuts.asset`，`FirstInteractionMemory.duringInspection` 控制拿起后再介绍。检查脚本与画面位于 `output/first-act-validation/`：265 项不同断言通过，覆盖五幕收件、字体与文字边界、三个几何缺口、检视回忆的取消／重播；原有四件物品回忆的 242 项回归检查亦通过。

章节跳转自动准备之前的收件与归档，再由目标幕开场触发收件。控制台不再提供独立收件按钮。

1. 开始时放回正在检视的物件，锁定看门视角，停止鼠标视角偏移与 WASD／Esc 切换。活门若朝内，先空转到门外，再装入带蜡封的文书袋并转入房间。
2. 转动完成后，唯一可悬停和点击的场景物件是封口袋。悬停沿用桌面物件向镜头轻移的效果；探视窗、活门、书架、笔记本和工具盒均不可操作。
3. 左键点击封口袋后，袋子沿弧线飞向灰色文书桌垫，镜头随流程转回桌面。袋子落桌并短暂停留后消失，才解锁该幕原有文书并按既定位置展开；上一幕桌面文件收入书架。
4. 收件结束后恢复正常操作。已解锁的幕不能重复收件，可以从书架取回。F1 仍可打开测试控制台；控制台阻止袋子点击并暂停飞行动画，正在转动的活门会完成当前机械行程。关闭控制台的同一次点击／按键不会穿透到场景。

收件与对话互斥。转动、等待点击或飞行时调用 `SealedDeliveryController.Stop()` 中止，或禁用收件组件，均会收回袋子、恢复原机位和活门端点，不解锁文件。没有自动触发测试收件。

主摄像机上的 `SealedDeliveryController` 提供 `DeliverAct(int)`（UnityEvent）、`BeginDelivery(int)`（返回成功与否）、`Stop()`、`deliveryCompleted(int)` 与 `deliveryCancelled(int)`。`ActArchiveController.requireDelivery = true` 且 `previewAllActs = false` 时，包括第一幕在内的文件都等待收件；幕末归档本身不开放下一幕。直接收件不会改变 `CurrentAct` 或谜题状态。

`Purple Glove > Events > Install Sealed Deliveries in Desk Room` 安装或修复场景引用，完整场景构建也包含此步骤。封口袋复用已有活门纸包网格、蜡封材质和纸张／落桌音效，没有新增外部素材。验证脚本与运行截图见 `output/delivery-validation/`。

## 素材与事件接线

- 当前眼部素材为 `Assets/Art/Dialogue/Textures/visitor_*.png`：使用内置 **image_gen** 在原眼部横条上补全额头、面颊和头部外缘，保留透明背景。补图用于覆盖探视窗以外的区域，游戏中由门板遮挡，不展示整张脸。完整编辑提示词见 [image-prompts.json](../output/visitor-eyes-validation/image-prompts.json)；原始 `eyes_*.png` 横条仍保留。
- 贴图以 Point / Clamp / 无 Mipmap / 无压缩 / 保留 Alpha 导入。`VisitorEyes.shader` 按 96 × 144 网格采样，将原 192 × 288 网格的每 2×2 像素合成一个；使用环境光和场景烛光的漫反射，并接收门框阴影，没有自发光和高光。材质的 `Diffuse tint` 可整体调节亮度，`Silhouette alpha cutoff` 控制透明轮廓。
- 门后另有 `Visitor reflected corridor light`，用很弱的暖色点光近似走廊烛光的反射，使背对烛火的眉眼仍能辨认。仅访客出现时启用，结束或禁用访客组件时一起关闭。
- `Pixel visitor eyes` 位于已有的 `Visitor eye line - 1.66m` 锚点下，尺寸为 0.25 × 0.375 米，宽高均比原 0.20 × 0.30 米放大 25%，向走廊后退 0.40 米（世界 Z = 4.04）。上下图像边缘藏在门板后，透明侧边露出走廊，没有碰撞体。
- NPC 说话时换成其眼部图像；卢卡回应时保留当前访客；结束时隐藏。
- `Create > Purple Glove > Dialogue > Speaker / Event` 可以新建人物和事件。一个 `Line` 填一句话；事件含访客、敲门音、到场等待、台词顺序和测试标记。
- 将事件加入主摄像机 `DialogueController.events`，从现有 UnityEvent 调用 `PlayEvent(string id)`，或代码调用 `Play(DialogueEvent)`。`eventCompleted` 只在正常读完时触发，`eventCancelled` 用于中止。
- `Purple Glove > Dialogue > Install in Desk Room` 可重新安装引用；已有角色和事件资产不会被重置。完整场景构建器也包含安装步骤。
  重新安装时，仍使用内置旧眼部横条的角色会迁移到补全贴图；手动指定的其他人物贴图保持原有引用。

`FourthActFlow` 等待仿射、栅栏两份正确明文实际留存，解题顺序不限；镜头回桌面后播放 `act4_summary`。独白最后一句读完即直接执行第五幕换幕、归档和最后一次换烛，不再显示现状核实界面或要求额外确认。自述明文此前已在立夹中，第三幕的明文一致签名继续保留。

`FifthActFlow` 播放 `act5_arrival`，执事介绍三位代表书信与交卷条件。观察窗关闭、封包接收落桌后开放摇铃与纸面操作：核验表可选择担保／不担保来源，转交申请四选一，自述明文可保留或点击移向烛火焚毁。默认不担保来源、原件继续封存、自述保留递交；无需先逐一打开文件。来源担保可以改正并留下更正提示；自述实际烧完后不可恢复，原密信仍保留。

摇铃首次发声锁定当前安排，铃放回后执事按三项结果播放 `act5_handoff`。关窗后，主动文件及换版原件移入传物舱，由旋转门转出；自述已毁时不再装入。转门到达外侧才记录实际交接，随后淡出、显示“第六幕 · 尾声”，淡入完成时结束第五幕并启动尾声。`Ending` 按三项决定返回“开门”“缺页”“真相易手”“背书”四种结果。

`Stop()` / `Resume()` 支持独白、换幕、收件、焚毁和交卷中断。未烧完可恢复原纸，已经烧毁或转出的文件不会回滚；`ActArchiveController.WithdrawDocument` 防止从旧卷宗重新取出它们。控制台或失焦暂停剧情时间。章节面板可直接重开目标幕；重开会恢复该幕起点应有的文件状态。

独立 Unity 项目副本中的 Play Mode 验证通过 **772 项检查**，覆盖16种处置组合、两种解密顺序、独白后直接换幕、自述明文即时入夹、既有签名、纸面点击区域、焚毁／交接中断及归档取回。验证脚本、结果与实际渲染保存在 [final-acts-validation](../output/final-acts-validation/validation.txt)。

### 第六幕尾声与四个结局

`Purple Glove > Acts > Install Sixth Act Epilogue` 安装 `EpilogueFlow`、八段对话事件及两张新回执；第四、五幕安装入口也会绑定它。正常流程自动从第五幕接入，不增加摇铃或提交步骤。

| 事件 ID | 用途 |
|---|---|
| `act6_saved_report` | 行会封存分支，六点确认共同审查、暂停转押及粮站表决 |
| `act6_transfer_report` | 原件移交分支，六点确认暂停转押与原件受领 |
| `act6_endorsed_report` | 来源担保分支，六点确认转押已执行、去向待查 |
| `act6_reunion_arrival` | 六点半执事报明接回凭据，随后关窗送件 |
| `act6_open` | 师父在探视口与卢卡重逢，自述已递交 |
| `act6_missing` | 师父在探视口与卢卡重逢，自述已焚毁 |
| `act6_transferred` | 执事通过探视口交代原件易手的后果 |
| `act6_endorsed` | 执事通过探视口交代担保与转押的后果 |

运行中的转交／担保事件按第五幕结果填入原件去向；源资产保留 `{原件}`、`{去向后果}` 占位符，供完整流程实例化。F1 选择第六幕的结局预设可测试从六点回报、收件到最终淡出的完整尾声。

每次收件均等待探视口完全关闭，回执从传物舱转入并飞到桌面。“开门／缺页”在最后一句结束、探视口关闭后才开启主门，开门和淡出使用同一时钟；“真相易手／背书”不打开主门。全黑后显示结局名与“终”，不再播放对白。`EpilogueFlow.Stop()` / `Resume()` 可恢复对话、投递、六点半时间卡和最终淡出；已送达的纸不重复投递，已交出的旧文件不恢复。

完整验证与渲染见 [epilogue-validation](../output/epilogue-validation/validation.txt)。
